## 一、系统概述

### 1\. 功能定位

本规范定义"一条事件怎么写才算合格"。它是事件内容生产的写作标准与数值标准，供人工填写或 AI 生成事件时对照执行，产物最终进入配置表 `events.json`，由游戏运行时直接加载。

本规范不负责：

* 事件系统规则（抽取、触发、连锁机制）——归主策划案 6.4 / 6.5；
* 逐事件策划案——每个事件的内容直接在配置表中填写，不单独成文。

上游依据：主策划案 V1.6（第六、七、八章）与《S\_骰子判定与能力系统\_系统规则》V2.4。与主策划案冲突时一律以主策划案为准。

### 2\. 玩法说明

事件是玩家每轮看到的"政治压力与选择单位"。本规范约束事件的三个组成部分：

1. **事件级**：标题、背景、难度档、触发门槛——决定玩家看到什么、事件何时出现、判定多难；
2. **方案级（×2）**：两个政治行动方案，各用不同帝王能力投骰——决定玩家怎么选；
3. **不作为级**：不处理时的后果——让"忽略"也成为有代价的选择。

### 3\. 用户体验目标

* 玩家一眼看懂矛盾双方与压力来源，不需要解读谜语。
* 玩家能猜到"这个方案为什么用这个能力"。
* 每个方案都有真实代价，不存在无脑最优解。
* 隐藏值不显示精确数字，但通过史官文本与区间反馈可感知。

### 4\. 名词定义

|名词|定义|
|-|-|
|事件|每轮提供的政治压力与选择单位，分日常 / 危机 / 重大三级|
|方案|玩家应对事件的具体政治行动，本规范指帝王能力方案|
|不作为|不处理事件，不掷骰，按事件配置结算后果|
|三档结果|完全成功 / 有条件成功 / 失败（主策划案 7.3）|
|隐藏值|不显示精确数字的状态。分两类：支持度类（平民支持度、旧姓支持度等）与灾变类（土地辐射风险、火穗锈病进度、人疫病进度等）|
|锈病 / 疫病|锈病是作物病（火穗锈病，`plague\\\\\\\_progress`）；疫病是人的病（另立字段，如 `flu\\\\\\\_progress`），二者不混用|
|能力|洞察（insight）/ 驭人（influence）/ 威仪（majesty）——两方案必须不同|
|事件难度|事件级静态难度档（difficulty，-3 极易 至 +3 极难 共七档，越大越难）。一属性两用：①判定阈值（只平移成功阈值，不修正骰值）②阶段权重倾斜（早期偏简单、后期偏难，见主策划案 6.5）。日常 -3\~+1、危机 +1\~+2、重大 +3|

## 二、系统规则

### 1\. 事件条目结构（模板）

每条事件由三部分组成，缺一不可：

|部分|字段|必填|说明|
|-|-|-|-|
|事件级|id|是|英文小写蛇形，唯一|
||等级|是|daily / crisis / major|
||标题|是|直白短句，避开规整四字格（原子化命名原则），能概括矛盾即可|
||背景|是|2\~3 句，直白交代冲突双方与压力来源|
||难度 difficulty|是|事件级静态难度档：日常 -3\~+1、危机 +1\~+2、重大 +3。一属性两用：判定阈值 + 阶段权重倾斜（主策划案 6.5）|
||触发条件|危机必填|支持 `any`（任一条件过线即触发）/ `all`（全部满足才触发）两种组合；资产类危机挂低/高两个门槛对应普通与严重两档；日常/重大不填|
||权重 / 冷却|否|日常权重由阶段难度系数自动决定（1 × 阶段系数），无需手填；危机权重由引擎按轮累计（过线 20、每滞留一轮 +5、被不作为 +10、上限 60），仅在需要偏离默认时填 `trigger_weight`；冷却日常 3、剧情类危机 6、资产类危机 0（主策划案 6.4）|
|方案级（×2）|方案名|是|直白动词短语，避开规整四字格，必要时禁用文言|
||能力|是|insight / influence / majesty 之一；两方案必须不同（两种骰子）|
||方向|是|一句话设计意图：得到什么、牺牲什么|
||效果 ×3|是|full / partial / fail 三档数值|
||史官文本 ×3|是|三档对应的叙事文本，直白|
|不作为级|不作为文本|是|选择不处理后会发生什么|
||不作为效果|是|按配置结算的 State 变化|
||不作为史官|是|不作为的结局叙述|

### 2\. 数值基准

数值为**建议基准，须经试玩校准**（主策划案十三阶段一第 18 条）。

|档位|可见 State 单项|隐藏值单项|要求|
|-|-|-|-|
|日常·完全成功|+10 \~ +60|±5 \~ ±30|解决当前矛盾，可带小额代价|
|日常·有条件成功|+5 \~ +30|±3 \~ ±15|约完全成功收益的 40%\~60%|
|日常·失败|-10 \~ -80|±5 \~ ±35|有真实痛感，但不一次打穿下限|
|危机|±80 \~ ±300|±15 \~ ±80|多 State 联动，后果显著|
|重大|全局量级|影响终局|与预言绑定，见主策划案 6.1|

数值规则：

* **能力修正不配置在事件中**：判定 = 2d6 + 君主能力修正（建卡决定）+ 其他修正（如有）。事件方案不携带能力修正，只声明使用哪种能力（主策划案 7.1）。
* **难度是事件级静态属性**：每条事件在 `difficulty` 字段标定难度档（-3 极易 / -2 很易 / -1 易 / 0 标准 / +1 难 / +2 很难 / +3 极难 共七档，越大越难），写死后不随玩家能力或轮次变化。一属性两用：只平移成功阈值（完全成功门槛 = 9 + difficulty、失败门槛 = 6 + difficulty，见骰子系统 V2.4）+ 决定阶段权重倾斜（主策划案 6.5）。**日常事件难度取 -3\~+1，更高的 +2 / +3 留给危机与重大：危机 +1\~+2、重大 +3。**
* **有得有失**：每个方案必须有真实代价，不允许无脑最优解。完全成功允许附带小代价，但主问题必须解决。
* **有条件成功必须"有条件"**：效果中体现范围受限、追加支出、支持度下降或后续承诺等条件（主策划案 7.3）。
* **有条件成功有两种形态（2026-9-2 补）**：不必然是"收益打折"，也可以是"收益保全、代价抬升"。设计时按方案性质二选一：

  * **形态 A·收益打折**：收益缩水（约为完全成功的 40%\~60%），代价与完全成功相当或略轻——适用于"成果不可分割"的方案（如一次性查案、一次判田）；
  * **形态 B·代价抬升**：收益基本保全，但代价显著加重（追加支出、支持度进一步下降、或引入本可避免的次生风险）——适用于"成果可保全、代价可控"的方案（如停炉检修、办庆典）。
  * 判定：若"成果本身二选一、拿不到就是拿不到"，用形态 A；若"成果能拿到、只差代价谈不拢"，用形态 B。
* **隐藏值可变幅大**：一次事件可明显增减隐藏值（日常 ±5\~±35 起步，危机更大），让不同选择在对局中快速分化，避免局局趋同。仍不显示精确数字，只经史官文本与区间反馈。
* **危机触发 = 条件组合 + 按轮累计加压**：每条危机写触发条件，支持 `any`（任一条件过线即触发）与 `all`（全部满足才触发）两种组合；资产类危机挂低/高两个门槛，对应普通与严重两档。过线后危机进池，基础权重 **20**，此时才开始按权重与其他事件竞争。此后每滞留一轮 +5，被"不作为"绕开再 +10，上限 **60**；只有当轮被处置、或触发条件回落才清零。事件链进度积满时权重跳至最高（必出）。
* **不打穿**：效果不得让 State 一次性越出上下限，设计时考虑 State 现状。
* **档位收益/代价比（2026-9-1 补）**：随档位改善，收益递增、代价递减。完全成功的代价不高于有条件成功——代价型方案（如"停种轮作"：以财政/GDP 换土地安全）full 的损失应小于 partial；收益型方案（如"火为先"）full 的风险成本应小于 partial。失败档无收益或带负面后果。

### 3\. 方案设计原则

* **每事件恰好两个方案**（正式版可配置大臣/国力路线，本规范只管能力方案）。
* **硬性要求：两方案使用不同能力（两种骰子）**。insight / influence / majesty 各选其一，不得相同。
* **建议（非强制）：方案对偶**，三选一：

  * 一利一弊（保护 X 牺牲 Y，反之亦然）；
  * 时间维度（短期收益 vs 长期隐患）；
  * 能力语义形成反差（一个安抚、一个强制）。
* **能力要与语义匹配**：洞察用于查案、识破、判断局势；驭人用于谈判、安抚、制衡；威仪用于宣令、震慑、强制（主策划案 4.1）。方案写法必须让玩家能猜出"这个方案为什么用这个能力"。
* **方向字段一句话说清**：格式为"采取此方案 → 得到什么，牺牲什么"。它是玩家决策时的主要信息（主策划案 3.2 信息公开原则）。
* **两方案不得雷同**：能力已强制不同；代价结构也避免雷同。

### 4\. 不作为设计

* 不作为不掷骰、不消耗资源，按配置结算（主策划案 6.3）。
* 不作为效果通常从以下类型选取，至少选一项：

  * 支持度下降；
  * 事件升级（后续以更严重形态回归）；
  * 开启后续危机（提高危机事件触发风险或累积事件链进度）；
  * 错过短期机会；
  * 极少数情况：让其他势力互相消耗，形成意外收益（须在文本中说明因果）。
* **不作为不是"轻微惩罚"，而是"局势自行发展"**：史官文本要有因果推进，让玩家感到"这件事没有消失，只是脱离了我的控制"。
* 不作为数值大致与"方案失败档"相当或略轻，但附带后续隐患（如事件链进度 +1）。
* 重大事件允许不作为，但不作为不取消事件，只把主动权交给局势（主策划案 6.3）。

### 5\. 文本写作规范

* **背景（2\~3 句）**：直白交代冲突双方与压力来源，不剧透结果，不留"二选一"痕迹。
* **标题**：直白短句，避开规整四字格（原子化世界观命名原则），能概括矛盾即可。
* **方案名**：直白动词短语，避开规整四字格，行为导向，让玩家一眼看懂在做什么。
* **史官文本三档（各一句，直白交代发生了什么）**：

  * 完全成功：问题解决，如带代价则坦然承认；
  * 有条件成功：有效但受条件限制，必须把"条件"是什么说清楚（"条件"既可是收益受限，也可是代价加重，见 2.2 两形态）；
  * 失败：核心问题未解决，因果成立。
* **文风：直白清晰，不故作玄虚**。标题可以凝练，但正文（尤其方案与史官文本）用平实白话，清楚交代"做了什么、得到什么、付出什么"。不堆砌修辞，不用谜语式表达。
* **禁用数字**：史官文本与背景中不出现任何具体数值（数值只存在于 effects）。
* **不剧透**：不泄露隐藏值精确数字，不预告未揭示的后续分支（主策划案 3.2）。
* **女性君主视角**：事件体现君主在权威、社会期待、派系关系与公共形象上的特殊处境（主策划案 1.3）。

### 6\. 等级差异

|等级|数值量级|方案侧重|写作重心|
|-|-|-|-|
|daily 日常|±10\~80|建议对偶|单一矛盾，可忽略，影响小|
|crisis 危机|±80\~300|代价必须显著|多 State 压力，必须决策|
|major 重大|全局|影响预言与终局|历史高潮，可被后世回望|

**危机触发：条件组合 + 按轮累计加压**（主策划案 6.4 / 6.5）。危机事件平时不进池（权重 0）；触发条件过线后进池，基础权重 **20**，此后按统一抽取公式与其他事件竞争：

* 每条危机在事件配置中写触发条件，支持 `any`（任一条件过线即触发）与 `all`（全部满足才触发）两种组合；
* 条件通常基于隐藏值（灾变类进度、支持度极端值）或可见 State（军力 / 领土 / 财政达到某个水位）；
* 资产类危机挂低 / 高两个门槛，对应普通与严重两档难度（+1 / +2）；
* 过线后每滞留一轮权重 +5，被玩家**不作为**再 +10，上限 60；只有当轮被处置、或触发条件回落才清零；
* **事件链升级**（由特定日常事件的不作为/失败累积）进度积满后，危机权重跳至最高（必出）。

示例（火穗生锈）：条件 A「火穗锈病进度 ≥ 5」或 条件 B「土地辐射风险 ≥ 50」，任一成立 → `husk_blight` 进池，基础权重 20；若这一年没解决，下一年 25、再下一年 30，以此类推，上限 60。

**重大事件**：不随机出现、不进统一池，由预言或君主目标条件满足后强制占一张卡位；以单卡进入选卡页（无可回避），难度档统一 **+3**，不参与阶段权重倾斜。

### 7\. 异常与边界情况

* 数值不得一次打穿 State 上下限；填表时需对照当前 State 范围。
* 同一事件两个方案能力不得相同（硬性校验项）。
* 隐藏值变化不直接显示数字，只经史官文本与区间反馈，配置时不得在文本中写精确值。
* 危机事件缺少触发条件视为无效配置（校验项）；条件支持 `any` / `all` 两种组合，不得写成三条以上扁平条件堆叠。

|background|string|是|直白背景，2\~3 句|
|difficulty|int|是|事件级难度档：日常 -3\~+1、危机 +1\~+2、重大 +3。一属性两用：判定阈值（完全成功门槛 = 9 + difficulty、失败门槛 = 6 + difficulty）+ 阶段权重倾斜（主策划案 6.5）|
|weight|int|否|统一池基础权重，默认 1；日常实际权重 = 1 × 阶段难度系数（引擎自动乘，无需手填）；危机未过线时不进池，过线后由运行时按「基础 20 + 累计压力」计算|
|cooldown|int|是|出场后冷却轮数：日常 3、剧情类危机 6、资产类危机 0（主策划案 6.4）|
|trigger|object|危机必填|触发条件块：`type` 取 `any`（任一条件过线即触发）/ `all`（全部满足才触发），`conditions` 为条件数组；资产类危机挂低 / 高两组门槛，对应普通与严重两档|
|trigger_weight|int|否|危机过线后的基础权重（默认 20）；仅在需要偏离默认时填。每轮累积 +5、被不作为 +10、上限 60 均由运行时处理，事件表不填|

**方案级：**

|字段|类型|必填|说明|
|-|-|-|-|
|id|string|是|方案唯一编号|
|name|string|是|直白动词短语，避开规整四字格|
|ability|enum|是|insight / influence / majesty；两方案必须不同|
|direction|string|是|得到什么、牺牲什么|
|effects|object|是|full / partial / fail 三档 State 变化|
|chronicle|object|是|三档史官文本|

**不作为级：**

|字段|类型|必填|说明|
|-|-|-|-|
|text|string|是|不处理会发生什么|
|effects|object|是|State 变化（扁平结构）|
|chronicle|string|是|不作为结局叙述|

**State 键（effects 内）**：可见值 `treasury` 财政、`population` 人口、`gdp` GDP、`military` 军力、`territory` 领土；隐藏值——支持度类 `civilian\\\\\\\\\\\\\\\_support` 平民支持度、`noble\\\\\\\\\\\\\\\_support` 旧姓支持度；灾变类 `radiation\\\\\\\\\\\\\\\_risk` 土地辐射风险（作物与土地）、`plague\\\\\\\\\\\\\\\_progress` 火穗锈病进度（**作物病**）、`flu\\\\\\\\\\\\\\\_progress` 人疫病进度（**人的病**，如坊区时疫 `flu\\\\\\\_raiding` 用）。灾变类按事件性质选用，锈病与人疫病不混用。

### 3\. 配置规则与关联关系

* 方案不配置能力修正（`ability\\\\\\\\\\\\\\\_modifier` 已废弃），能力修正由君主建卡提供（主策划案 7.1）。
* 事件难度 `difficulty` 为事件级必填（日常 -3~+1、危机 +1~+2、重大 +3）；方案不单独标难度。
* 危机事件的 `trigger`（`any` / `all` 条件组合）+ `trigger_weight`（过线基础权重，默认 20）与主策划案 6.4 统一池机制对应；权重随滞留轮数累计、被不作为额外加压；事件链进度由不作为效果中的事件链条件驱动，积满后权重取最高。
* 日常基础权重固定 1，运行时再乘阶段难度系数（主策划案 6.5）；`trigger_chance`（旧顶替概率）已废弃删除。

### 3.8 危机事件的配置与调用清单

危机事件不只填写 `type: crisis`，还必须同时完成以下配置：

1. **基础权重**：危机未过线时不进池；触发条件过线后，由运行时按「基础 20 + 累计压力」计算权重（每滞留一轮 +5、被不作为 +10、上限 60）。废弃事件或终局事件也可用 `weight = 0`，但含义不同：危机是等待触发，废弃 / 终局是永久不抽取。
2. **难度**：剧情类危机 `difficulty = 1`，资产类严重档 `difficulty = 2`；危机不参与日常的阶段难度加权（出现与否由触发条件决定）。
3. **冷却**：剧情类危机 `cooldown = 6`；资产类危机 `cooldown = 0`（进出池完全由触发条件是否过线决定）。
4. **触发条件**：必须配置触发条件，支持 `any`（任一成立即激活）/ `all`（全部满足才激活）两种组合；不得写成三条以上扁平条件堆叠。
5. **触发后权重**：条件成立后危机进池，权重 20 起；每滞留一轮 +5，被不作为 +10，上限 60；被处置或条件回落则清零。
6. **调用方式**：危机仍与日常事件共用统一抽取池，不直接替换当前事件；权重变化后参与下一次抽取。重大事件不进入该池。
7. **能力点奖励**：危机被玩家主动处理并完成结算后，奖励 1 点能力点；失败或不作为不奖励。单局能力点奖励上限为 5 点，重大事件不奖励能力点。

## 五、补充说明

### 1\. 示例事件（按本规范撰写）

以"灯和炉抢火籽"（lamp\_festival）为例，见附录 A。示例包含完整三部分结构，可直接复制为配置条目。

### 2\. 验收标准

1. 每条事件包含完整三部分（事件级 + 方案 ×2 + 不作为），必填字段齐全。
2. 两方案能力不同；每个方案有真实代价，无无脑最优解。
3. 数值在档位区间内；隐藏值按量级；有条件成功 ≈ 完全成功收益的 40%\~60%；不越 State 上下限。
4. 危机事件配置了 `trigger`（`any` / `all` 条件组合）与 `trigger_weight`（过线基础权重，默认 20），形式符合主策划案 6.4 / 6.5。
5. 事件 `difficulty` 在所属等级区间内（日常 -3~+1、危机 +1~+2、重大 +3）。
6. 文本直白、无数字、不剧透；标题与方案名避开规整四字格。
7. 不作为后果存在且为"局势自行发展"，重大事件不作为不取消事件。
8. 事件内容与主策划案冲突时以主策划案为准（校验项）。
