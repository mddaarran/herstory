# Godot Demo 编程协作规则

## 实现目标

优先实现可验证的核心循环：事件 → 方案 → 大臣 → 骰子判定 → State 变化 → 史官反馈。

## 代码原则

- 使用清晰、可拆分的 Godot 场景和 GDScript；避免为 Demo 过早引入复杂框架。
- 事件、大臣与 State 效果优先数据驱动，便于策划迭代。
- 将规则计算与 UI 展示分开，保证结果可测试、可解释。
- 对随机结果保留可复现测试入口（例如可配置随机种子或测试模式）。
- 每次修改说明影响的场景、脚本、数据与验证方式。
- 引用文件、脚本、数据与 ID 时一律使用原始名称（如 `herstory/data/events.json`、`GameState.gd`、`insight`），不翻译、不改写大小写与分隔符。

## 建议最小模块

- `GameState`：保存可视和隐藏 State。
- `EventManager`：选择、触发并结算事件。
- `Minister`：提供修正和特殊能力。
- `Resolution`：处理骰子与结果等级。
- `Chronicler`：根据结果生成反馈文本。

模块名称为建议，创建实际项目时可按 Godot 架构调整。
