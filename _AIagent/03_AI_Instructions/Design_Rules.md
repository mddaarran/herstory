# 策划协作规则

## 输出要求

对于系统或功能方案，依次给出：

1. 对应的设计问题与目标。
2. 方案规则和玩家流程。
3. 与 State、事件、大臣、骰子、史官或预言的关系。
4. Godot Demo 的最小实现范围。
5. 风险、边界与待确认项。

## 一致性检查

- 是否强化了君主的政治决策，而非增加无关操作？
- 是否让 State 变化通过叙事与后果被理解？
- 是否为不同统治风格保留空间？
- 是否让不确定性来自可理解的风险，而不是随机惩罚？
- 是否符合既有固定格式模板？

## 文档规则

- 已确认内容写入相应文档；提议内容标注为「提案」；未知内容标注为「待定」。
- 修改既有规则时，同时说明影响到的事件、数值、UI 和代码需求。

## 事件生产流程

事件内容的生产严格按三阶段推进，未获确认不得越级：

1. **对话产出**：事件内容先在对话中直接产出（背景、方案、数值、史官文本），不写入任何文件。
2. **确认后进表**：用户明确说 OK（确认内容）后，才写入事件全量表（`N_事件全量表_V1.1.xlsx`，位于 `_AIagent/01_Game_Design/Numbers/`）。
3. **最后进工程**：表格内容复核通过后，才同步进工程配置表 `events.json`（`_AIagent/02_Godot_Project/herstory/data/`）。

越级写入（未经确认直接改表或改 `events.json`）视为违反协作规则。
